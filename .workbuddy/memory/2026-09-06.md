## 后续：已给 bootstrap_project.py 加入子模块自愈加固（用户确认"加入"）
改动文件：`scripts/bootstrap_project.py`（唯一改动文件）

新增/修改的函数：
- `has_submodule_content(submodule_dir)` — 判断子模块工作区是否真有内容。**排除 `.git` 条目本身**：只剩 `.git` 的目录代表 gitlink 已注册但 checkout 从未落地，正是要识别的坏状态。
- `ensure_submodule_checkout(target_dir, submodule_dir, submodule_path)` — 空则 `git submodule update --init --recursive`；若仍空（git 因 gitlink 与 index 匹配而把 update 变成 no-op），则 `git submodule deinit -f` + 再次 update 强制重建。
- `is_submodule_registered(target_dir, submodule_path)` — 通过 `git config --file .gitmodules --get submodule.<path>.path` 判断是否已注册。
- `add_submodule()` — 原逻辑 `if submodule_dir.exists(): return` 是故障根源（空目录直接短路返回）。改为 `has_submodule_content()` 判断；且已注册时**跳过 add**（否则 git 报 `already exists in the index`），直接走 checkout；add 之后也补一次 checkout。
- `run_initializer()` — 签名加 `submodule_path`；找不到 initializer 时先尝试 checkout 再重新解析一次（兜底）。
- `main()` — 调用链加入 `ensure_submodule_checkout`。

**踩坑记录**：
1. 错误路径测试会把 git 的 `fatal: not a git repository` 漏到测试输出，看起来像测试挂了。`contextlib.redirect_stderr` 无效（子进程继承真实 fd），必须 fd 级 `os.dup2(1/2 → devnull)`。
2. fd 级重定向的 finally 里**必须先 `sys.stdout.flush()` 再 `os.dup2` 恢复**，否则 Python 缓冲的文本在恢复后才落地，泄漏到测试报告末尾。
3. 临时目录清理用 `shutil.rmtree(onerror=...)` 加 `chmod(S_IWUSR)`，因为 git object 文件是 444 只读位，Windows 上直接删会 PermissionError。
